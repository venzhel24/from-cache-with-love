Ключевые термины

  • Hit rate / miss rate
  • TTL (Time To Live)
  • Тёплый / холодный кеш
  • Stale data
  • Memory usage, eviction rate

Инвалидация

  • По времени (TTL)
  • По событию (data change)
  • Tag-based (зависимости)
  • Ручная (manual)

Цепочка кешей (HTTP Flow)

DNS-кеш

  • Кеш IP-адресов
  • Локальный и облачный резолвер
  • Ускорение разрешения имён
Очистка DNS-кеша:
Windows: ipconfig /flushdns
macOS: sudo killall -HUP mDNSResponder
Linux: sudo systemd-resolve --flush-caches

CDN

  • Кеширование статики (JS, CSS, images)
  • Cloudflare, AWS CloudFront, Яндекс.CDN
  • Снижение RTT, защита от DDoS
Очистка CDN-кеша:
• В панели управления: "Purge Cache"
• API: curl -X POST "https://api.cloudflare.com/client/v4/zones/{zone_id}/purge_cache"
• Cache-busting: style.css?v=1.2.3

Браузерный кеш

  • HTTP-кеш (Cache-Control, ETag)
  • localStorage, sessionStorage, IndexedDB
  • Service Workers (PWA)
Очистка браузерного кеша:
• Ctrl+Shift+Delete (универсальное сочетание)
• Ctrl+F5 (жёсткое обновление страницы)
• Chrome: Меню → Дополнительные инструменты → Удаление данных
• Firefox: Меню → Настройки → Приватность и защита → Удалить данные

Reverse Proxy

  • Кеширование HTTP-ответов
  • Nginx, Varnish
  • Разгрузка бэкенда
Очистка Nginx proxy-кеша:
• rm -rf /path/to/nginx/cache/*
• PURGE-запрос: curl -X PURGE http://site.com/page
• Через API или конфиг с proxy_cache_purge

Nginx: типы кеширования

  • Кеширование статики — CSS, JS, изображения, шрифты
  • Proxy cache — HTTP-ответы от бэкенда
  • FastCGI cache — кеш PHP/динамических запросов
  • Auth cache — кеш результатов аутентификации

Nginx: кеширование статики


location ~* \.(jpg|jpeg|png|gif|ico|css|js|woff2?|ttf|svg)$ {
    expires 30d;
    add_header Cache-Control "public, max-age=2592000";
    add_header Vary Accept-Encoding;
}
Очистка: Нет серверного кеша, только браузерный.
Решение: cache-busting (style.css?v=1.2.3)

Nginx: Proxy Cache


        # Настройка зоны кеширования
        proxy_cache_path /data/nginx/cache
            levels=1:2
            keys_zone=my_cache:100m
            max_size=10g
            inactive=60m;

        location / {
            proxy_pass http://backend;
            proxy_cache my_cache;
            proxy_cache_valid 200 302 10m;
            proxy_cache_valid 404 1m;
            add_header X-Proxy-Cache $upstream_cache_status;
        }

Кеш на уровне приложения

Bitrix: типы кеша

  • Управляемый кеш (Managed Cache), Тегированный кеш (Tagged Cache)
  • Неуправляемый кеш (CACHE_TIME)
  • Композитный кеш
  • Кеш шаблонов, настроек, ORM
Очистка кеша Bitrix:
• Админка: Настройки → Автокеширование → Очистка файлов кеша
• Через api
• Вручную: rm -rf /bitrix/cache/* && rm -rf /bitrix/managed_cache/*

Bitrix: Управляемый кеш

        
            $cache = \Bitrix\Main\Data\Cache::createInstance();

            if ($cache->initCache(3600, 'catalog_data', '/catalog/')) {
                $data = $cache->getVars();
            } elseif ($cache->startDataCache()) {
                $data = getCatalogData();
                $cache->endDataCache($data);
            }

Bitrix: Тегированный кеш


        $cache = \Bitrix\Main\Data\Cache::createInstance();
        if ($cache->startDataCache(3600, 'catalog_items_5', '/catalog/', ['iblock_id_5'])) {
            $items = \CIBlockElement::GetList([], ['IBLOCK_ID' => 5]);
            $cache->endDataCache($items);
        } else {
            $items = $cache->getVars();
        }

        // Инвалидация
        \Bitrix\Main\Data\TaggedCache::clearByTag('iblock_id_5');

Bitrix: очистка кешей


            // Управляемый кеш
            $GLOBALS["CACHE_MANAGER"]->CleanAll();
            $GLOBALS["stackCacheManager"]->CleanAll();

            // Кеш меню
            $GLOBALS["CACHE_MANAGER"]->CleanDir("menu");
            CBitrixComponent::clearComponentCache("bitrix:menu");

            // Html кеш
            $page = \Bitrix\Main\Composite\Page::getInstance();
            $page->deleteAll();

            // по ключу
            $cache = \Bitrix\Main\Data\Cache::createInstance();
            $cache->clean($uniqueString, $initDir);


            // По директории
            $cache = \Bitrix\Main\Data\Cache::createInstance();
            $cache->cleanDir($initDir);

            // По тегу
            $taggedCache = \Bitrix\Main\Application::getInstance()->getTaggedCache();
            $taggedCache->clearByTag('iblock_id_2');

            // Все теги
            $taggedCache = \Bitrix\Main\Application::getInstance()->getTaggedCache();
            $taggedCache->deleteAllTags();

            // Для элементов инфоблока
            \Bitrix\Iblock\ElementTable::getEntity()->cleanCache();
            // Для любой ORM сущности
            $entity::getEntity()->cleanCache();

Symfony: Tag-aware Cache


        $cache->get('products_list', function (ItemInterface $item) {
            $item->tag(['products', 'category_5']);
            return $this->fetchProducts();
        });

        // Инвалидация:

  • Data Cache
  • Full Route Cache

Очистка кеша Next.js:
• revalidateTag('users')
• revalidatePath('/dashboard')

Request Memoization

          const res = await fetch('https://api.example.com/data')
          return res.json()
        }

        // В одном рендере:
        const data1 = await getData() // запрос отправляется
        const data2 = await getData() // берётся из кеша (HIT)

Data Cache


            // Кешировать ответ (по умолчанию в Next.js 14)
            fetch('https://...', { cache: 'force-cache' })

            // Не кешировать (по умолчанию в Next.js 15)
            fetch('https://...', { cache: 'no-store' })

            // Кешировать с ревалидацией каждые 60 секунд
            fetch('https://...', { next: { revalidate: 60 } })

            // С тегами для групповой инвалидации
            fetch('https://...', { next: { tags: ['users'] } })

Next.js Cache Invalidation


        import { revalidateTag, revalidatePath } from 'next/cache'

        revalidatePath('/dashboard')

            await updateUser()
            revalidateTag('users')
            return Response.json({ success: true })
        }

Стратегии кеширования

Cache-aside (Lazy Loading)

  • Приложение проверяет кеш
  • При промахе — читает из источника
  • Сохраняет в кеш

Read-through

  • Приложение запрашивает данные
  • Кеш сам читает из источника при промахе
  • Кеш кэширует ответ

Write-through

  • Запись одновременно в кеш и источник
  • Гарантия согласованности
  • Высокая нагрузка на запись

Write-behind (Write-back)

  • Запись только в кеш
  • Асинхронная запись в источник
  • Риск потери данных

Refresh-ahead (Prefetch)

  • Обновление кеша до истечения TTL
  • Снижение latency
  • Требует прогнозирования

Cache warming

  • Предзаполнение кеша при старте
  • Для критичных данных
  • Снижает нагрузку на холодный старт

Типовые ошибки

  • Cache stampede
  • Hot keys
  • Thundering herd
  • Memory leak
  • Stale data

Безопасность

  • Изоляция кеша (multi-tenant)
  • Cache poisoning
  • Минимум PII в кеше
  • Шифрование чувствительных данных

Когда НЕ кешировать

  • Часто меняющиеся данные
  • Персонализированный контент
  • Критичные по актуальности
  • Редко запрашиваемые данные

Современные тренды

  • Edge Computing (Cloudflare Workers)
  • ML-driven кеширование
  • Serverless кеширование
  • Адаптивные TTL
